# Docker LND (testnet via neutrino)

Guide to run a Lightning Network Daemon node in the BitQuest dev
environment, to test proof verification `kind=CHANNEL` on testnet
end-to-end.

**Backend**: neutrino (no local bitcoind required — sync via SPV).
**Network**: testnet (bitcoin testnet3 for now on the LND side, not testnet4).
**Target audience**: developers who want to exercise the full BitLab
Phase 3 loop without depending on an external node.

> ⚠️ **Dev only.** The wallet password and seed used are not
> production-safe. The proposed infra is opt-in via a Docker profile
> and is not started by default.

## Start the LND container

The service is defined in `docker-compose.dev.yml` under the `lnd`
profile. It is **not started** by a standard `docker compose up`.

```bash
docker compose -f docker-compose.dev.yml --profile lnd up -d lnd
```

Check that the container is running:

```bash
docker ps --filter name=bitquest-lnd
docker logs -f bitquest-lnd   # follow testnet sync logs
```

Initial sync via neutrino takes **10-30 min** depending on the
connection (the testnet block filter is lightweight, no full
download). The container is usable as soon as `tls.cert` is
generated, but graph queries will not return results until after
sync.

## Initialize the wallet (one-time)

LND starts without a wallet: `GET /v1/getinfo` returns 404 as long as
no wallet is created and unlocked. The following script automates the
creation (idempotent — stops if the wallet already exists).

```bash
bash scripts/lnd/init-wallet.sh
```

It calls the REST API `POST /v1/genseed` then `POST /v1/initwallet`
with a cipher seed generated by LND and the default password
`bitquest-dev-password-insecure`. To use a custom password:

```bash
LND_WALLET_PASSWORD=my-password bash scripts/lnd/init-wallet.sh
```

After success, `admin.macaroon` + `readonly.macaroon` are generated in
`/root/.lnd/data/chain/bitcoin/testnet/` (visible via the Docker volume
`bitquest_lnd_data`).

## Extract credentials for BitQuest

```bash
bash scripts/lnd/extract-creds.sh
```

Displays something like:

```
# --- LND credentials (generated 2026-11-11T01:30:00Z) ---
LND_REST_URL=https://bitquest-lnd:8080
LND_MACAROON_HEX=0201036c6e64...
LND_TLS_CERT_B64=LS0tLS1CRUdJTi...
# ------------------------------------------------------------------
```

Copy these three lines into an `.env` or `.env.local` at the project
root, then restart `bitquest-dev` so Next.js re-reads the env vars:

```bash
docker compose -f docker-compose.dev.yml restart bitquest-dev
```

**Note on hostname**: `bitquest-lnd` resolves via the internal Docker
compose network (the `bitquest-dev` and `bitquest-lnd` containers
share the same network). From the Mac host, the URL would be
`https://localhost:8081` (mapped port). `extract-creds.sh` uses
`LND_HOSTNAME=bitquest-lnd` by default; for the host:
`LND_HOSTNAME=localhost LND_PORT=8081 bash scripts/lnd/extract-creds.sh`.

## Check the integration

With the wallet initialized and env loaded on the BitQuest side:

```bash
# 1. LND status
docker exec bitquest-lnd lncli --network=testnet getinfo

# 2. BitQuest status (admin health)
curl http://localhost:3000/api/health | jq

# 3. Test a channel lookup (once testnet is partially synced):
#    good testnet scids are rare, use a known chan_id or wait
#    until you have a real proof to submit.
```

The end-to-end flow:
1. Learner opens an `ln_channel` quest (currently `lightning` is still
   `SIMULATED`, to be migrated once LND is stable).
2. BitLabProofStep calls `/api/bitlab/challenge` → JWT.
3. BitLabProofStep calls `/api/bitlab/proof` with `kind=CHANNEL`.
4. Route handler `resolveChannel(network, scid)` → LND dispatcher.
5. `getChannelViaLnd` queries `GET /v1/graph/edge/{chanId}` via REST
   with the macaroon hex in the `Grpc-Metadata-macaroon` header, cert
   pinned via `LND_TLS_CERT_B64`.
6. Result normalized to `ChannelInfo`, persisted in `BitLabProof`.

## Full reset

If you want to start fresh (new wallet, etc.):

```bash
docker compose -f docker-compose.dev.yml --profile lnd down
docker volume rm bitquest_lnd_data   # ⚠️ wipes wallet + chain state
docker compose -f docker-compose.dev.yml --profile lnd up -d lnd
bash scripts/lnd/init-wallet.sh
bash scripts/lnd/extract-creds.sh
```

## Troubleshooting

- **`init-wallet.sh` fails with a TLS error**: `tls.cert` is not yet
  generated or the container just started. Wait 10-20 s and retry.
- **`/v1/getinfo` returns `server is still in the process of starting`**:
  neutrino is syncing. Wait or check the logs.
- **Macaroon hex copied but BitQuest refuses requests (401)**: the
  macaroon must be `readonly.macaroon` (or `admin.macaroon`), not
  `invoice.macaroon`. `extract-creds.sh` uses readonly by default.
- **TLS error from bitquest-dev**: the cert is generated for
  `localhost` + `bitquest-lnd` (thanks to `--tlsextradomain`). If you
  change the hostname, remember to regenerate the cert (`rm tls.*` in
  the container then restart lnd).
